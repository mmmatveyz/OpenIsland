# Product Map — что откуда и что дальше

Документ отвечает на вопрос «что где»: какие функции островка пришли из апстрима, какие сделаны нами, что не реализовано и что ещё осталось «чужим» в идентичности. Основа для решения, что вырезать и что развивать.

Составлено по фактическому коду `desktop/OpenIsland` (~19k строк C#/XAML, 84 файла `.cs`) на текущий момент.

---

## 1. Происхождение

| Источник | Что это | Объём |
| :--- | :--- | :--- |
| **Апстрим** `mihailkotovski/DynamicIsland` | Готовый нативный островок на C# WPF: окно-оверлей, пружины, стекло, медиа, тексты песен, таймер, OBS, полка, погода, QR, оформление, обновление | ~85% кода |
| **Наше** (OpenCode Hub) | Интеграция с локальным агентом OpenCode, хоткей, персоны, self-test, CI/скрипты сборки, доки, переносимые логи/токен | ~15% кода |

Практический вывод: апстрим — это «железо» островка (отрисовка, физика, интеграции). Наш продукт начинается там, где появляется OpenCode. Всё остальное сейчас — чужие фичи, которые работают, но не отражают нашу идентичность.

## 2. Карта функций

Состояние: `ок` — работает, `частично` — есть оговорки, `план` — не реализовано.

### 2.1. Ядро островка (апстрим, `ок`)
Прозрачное topmost-окно без кражи фокуса, пружинная физика, стеклянные поверхности, морфинг капсулы, пузыри-уведомления, скрытие в полноэкранных приложениях, автозапуск.

- `MainWindow.xaml` (+ `.Shape.cs`, `.Transitions.cs`, `.Notices.cs`), `Spring.cs`, `Motion.cs`, `Liquid.cs`, `Goo.cs`, `Glass.cs`, `Squircle.cs`, `Aura.cs`, `Shimmer.cs`, `StarField.cs`, `DotMatrix.cs`, `Visuals.cs`, `DrawingSurfaces.cs`, `DesktopComposition.cs`, `Native.cs`, `FrameLoop.cs`, `DelayedAction.cs`, `App.xaml(.cs)`.

### 2.2. Системный статус (апстрим, `ок`)
Громкость, заряд, индикатор наушников, сеть, DND.

- `MainWindow.Status.cs`, `MainWindow.Headset.cs`, `Headset.cs`, `AudioService.cs`, `CoreAudio.cs`, `NetworkService.cs`.

### 2.3. Медиаплеер (апстрим, `ок`)
Системная медиасессия (GSMTC): обложка и палитра из неё, перемотка, прогресс, эквалайзер/спектр, источник трека.

- `MediaService.cs`, `MainWindow.Media.cs`, `MainWindow.Seek.cs`, `Cover.cs`, `CoverPalette.cs`, `SourceApp.cs`, `PlayerBar.cs`, `Scrubber.cs`, `LineBar.cs`, `BandMeter.cs`, `Equalizer.cs`, `SpectrumService.cs`, `SpectrumAnalyzer.cs`, `SpectrumLevels.cs`, `Skip.cs`.

### 2.4. Тексты песен (апстрим, `ок`, но много внешних API)
Синхронные тексты с эффектами, строка у курсора, источники: lrclib, Deezer, NetEase, QQ Music, Kugou, Paxsenix.

- `LyricsService.cs`, `LyricsCatalogues.cs`, `MainWindow.Lyrics.cs`, `MainWindow.PointerLyric.cs`, `Lyric.cs`, `CompactLyric.cs`, `PointerLyric.cs`, `Parting.cs`, `LyricPreview.cs`.

⚠️ Риск: 5–6 сторонних lyric-API, часть — китайские сервисы. Сетевые запросы уходят наружу; для «своего продукта» это надо пересмотреть.

### 2.5. Таймер / будильник (апстрим, `ок`)
Преcеты 5–45 мин, пауза, кольцо прогресса, звонок и пульс при завершении.

- `MainWindow.Timer.cs`, `Countdown.cs`, `Alarm.cs`, `Ring.cs`.

### 2.6. Запись OBS (апстрим, `ок`)
Управление записью через OBS WebSocket 5: старт/стоп/пауза, время, размер файла, сцена. Читает порт и пароль из конфига OBS.

- `ObsService.cs`, `MainWindow.Record.cs`.

### 2.7. Полка файлов (апстрим, `ок`)
Drag & drop файлов на островок, превью, перенос файлов в другие приложения, хранение списка между запусками (реестр).

- `Shelf.cs`, `ShelfTile.cs`, `MainWindow.Shelf.cs`.

### 2.8. Погода (апстрим, `ок`)
Геолокация Windows + прогноз Open-Meteo, страница погоды и часы.

- `WeatherService.cs`, `MainWindow.Weather.cs`.

### 2.9. QR-код (апстрим, `ок`)
Скан области экрана или всего экрана (ZXing), показ QR, копирование в буфер.

- `QrReader.cs`, `AreaPicker.cs`, `MainWindow.Qr.cs` (+ пакет `ZXing.Net`).

### 2.10. Оформление и настройки (апстрим, `ок`)
Страницы меню: настройки, оформление, тексты песен. Масштаб, отступ, стекло, фон (матрица/звёзды), акцент, эффекты текста. Всё хранится в реестре.

- `MainWindow.Menu.cs`, `Settings.cs`, `Toggle.cs`, `Segments.cs`, `RowList.cs`, `BackdropPreview.cs`, `Icon.cs`, `Digits.cs`, `Puddle.cs`, `ChipCorners.cs`.

### 2.11. Обновление (апстрим, **выключено до появления нашего репозитория**)
Страница «Обновление»: версия, changelog, скачивание exe, сверка хеша, автоперезапуск.

- `Updater.cs`.
- ✅ Дыра закрыта: репозиторий задаётся `const string Repository`; пока он пуст, `IsConfigured == false`, `CheckAsync` выходит сразу, страница показывает «обновление не настроено», а кнопка «Обновить и перезапустить» отключена. Чужой бинарник скачать нельзя. Включим, когда появится URL нашего репозитория.

### 2.12. OpenCode AI Hub — **наше**
REST + SSE клиент, сессии, модели, промпты, стриминг ответа, разрешения, персоны, горячая клавиша, self-test.

- `OpenCodeService.cs` (1295 строк — самый большой модуль), `MainWindow.OpenCode.cs`, `OpenCodeSelfTest.cs`, XAML-секция OpenCode, `Native.cs` (хоткей + активация), `tools/agency-agents`.
- Состояние: `ок`. Роадмап-хвосты — в §4.

## 3. Идентичность: что ещё «чужое»

Это не про функции, а про то, что продукт всё ещё носит чужое имя. Статус: ✅ — сделано, ⏳ — осталось.

| Место | Было | Стало | ✅ |
| :--- | :--- | :--- | :--- |
| `Updater.cs` | чужой GitHub-репозиторий и ассет `DynamicIsland.exe` | `Stage.NotConfigured`: апдейтер выключен, чужой бинарник не скачивается; репозиторий задаётся `const string Repository` | ✅ |
| `Settings.cs` | реестр `HKCU\Software\DynamicIsland` | `HKCU\Software\OpenIsland` + авто-миграция значений при первом чтении | ✅ |
| `Autostart.cs` | Run-значение `DynamicIsland` | `OpenIsland` (+ миграция и удаление старого) | ✅ |
| `DynamicIsland.csproj` | нет `ApplicationIcon`, нет `Version/Product/Company` | `Version 1.0.0`, `Product/Company/AssemblyTitle/Description/Copyright`, `ApplicationIcon=Assets\OpenIsland.ico` | ✅ |
| `app.manifest` | `name="DynamicIsland.app"` | `OpenIsland.app` | ✅ |
| Иконка приложения | отсутствовала | `Assets/OpenIsland.ico` (7 кадров 16–256, тёмная капсула + индиго-циан ободок + искра) | ✅ |
| Трей | кода не было вообще | `MainWindow.Tray.cs` + `Native.cs`: `Shell_NotifyIcon`, меню (Открыть / Скрыть-Показать / Настройки / Выход), двойной клик — показать | ✅ |
| `desktop/OpenIsland/DynamicIsland.exe` | лежал в исходниках | удалён | ✅ |
| `README.md` (в `desktop/OpenIsland`) | чужой README с чужими фичами | переписать под OpenIsland — сделаю **после** вырезания чужих модулей, чтобы не описывать то, что удаляем | ⏳ |
| Пространства имён | `namespace DynamicIsland` во всех 84 файлах | решено **отложить**: массовая механическая правка без пользы для пользователя | ⏳ |

Итого по идентичности: всё, что видит пользователь (имя окна/exe, иконка, трей, реестр, автозапуск, README), переведено на `OpenIsland`. Остаётся только внутреннее пространство имён — косметика для разработчика, не для релиза.

## 4. Чего ещё нет (из роадмапа)

- **Мониторинг ПК**: CPU (общая и по ядрам), RAM, GPU, диск, сеть, температура; adaptive 1–3 с. В Electron-легаси был `electron/ipc/system-monitor.ts`. В WPF-версии модуля нет.
- **Dev-процессы и порты**: список Node/Python/Docker/Go и занятых локальных портов.
- **Быстрые действия**: буфер обмена, запуск утилит.
- **OpenCode**: диффы (`/api/session/{id}/diff`), полная история сообщений, Windows-уведомление о завершении задачи.
- **Персоны**: полноценный выбор из 380+ ролей с поиском и категориями; сохранение последней персоны.
- **Релиз**: установщик (Inno Setup/MSIX), portable-сборка, подпись exe.

## 5. Предлагаемый порядок работ

Порядок учитывает твои приоритеты (идентичность, свои виджеты, стабильность, «сначала покажи, что где»).

### Шаг 1. Идентичность — ✅ **выполнено**
Быстрый, заметный и низкорисковый результат. Ничего не ломает по функциям.
1. ✅ Свой реестр + миграция со `Software\DynamicIsland`; свой Run-ключ.
2. ✅ Закрыта дыра с обновлением: апдейтер выключен (`NotConfigured`), чужой бинарник не скачивается; репозиторий задаётся одной константой.
3. ✅ Своя иконка приложения + метаданные (`Version`, `Product`, `Company`) + `app.manifest`.
4. ✅ Трей: иконка, контекстное меню (Открыть / Скрыть-Показать, Настройки, Выход).
5. ✅ Удалён мусорный exe из исходников; ⏳ свой README — после вырезания чужих модулей.

Осталось: переименование пространства имён `DynamicIsland` → `OpenIsland` (отложено), переписать `desktop/OpenIsland/README.md` (после вырезания чужих модулей) и включение апдейтера после появления URL нашего репозитория.

Оценка: **M** (полдня–день), без изменения поведения островка.

### Шаг 2. Ревизия чужих функций — **решаем вместе**
Кандидаты на вырезание (нужно твоё решение по каждому):
- Запись OBS — узкая, требует OBS WebSocket. `ObsService.cs` + `MainWindow.Record.cs`.
- Полка файлов — своя экосистема, конфликтует с «пультом агента». `Shelf*`.
- Погода — внешний API + геолокация. `WeatherService`, `MainWindow.Weather.cs`.
- QR-код — self-contained утилита. `QrReader`, `AreaPicker`, `MainWindow.Qr.cs`, пакет ZXing.
- Тексты песен — 5–6 внешних API + много кода (`PointerLyric.cs` — 444 строки, `MainWindow.Lyrics.cs` — 306).
- Оформление/обои (матрица/звёзды) — косметика.
- Обновление через GitHub — см. §3.

Я дам отдельную оценку «сколько строк/модулей уйдёт и что сломается» по тем пунктам, которые ты выберешь.

### Шаг 3. Свои виджеты (роадмап)
- Мониторинг CPU/RAM/GPU/диск/сеть с адаптивным интервалом.
- Список dev-процессов и портов.
- Быстрые действия.

Это ровно та ниша, где островок полезен как «пульт разработчика» и не дублирует апстрим.

### Шаг 4. Стабильность и тесты
- Юнит-тесты на критичное: `Settings` (реестр/миграция), `OpenCodeService` (парсинг, ретраи, `Esc`), `Updater` (хеш), `Countdown`.
- CI: уже есть `ci.yml`/`release.yml` — добавить прогон тестов и self-test.
- Диагностика OpenCode: демон недоступен, сменился порт, истёк токен, сессия удалена.
- Краш-репорты и кольцевой лог уже есть (`%LOCALAPPDATA%\OpenIsland\logs`).

## 6. Технический долг (мелочи, но стоит знать)

- `OpenCodeService.cs` — 1295 строк в одном файле, стоит разбить на `OpenCode.Client/Events/Sessions/Models`.
- Дублирование логики таймеров OpenCode было (устранено при правке «0:00»): теперь единый `UpdateOpenCodeTimer`.
- `desktop/` и `scripts/` не в git-истории (untracked) — код проекта фактически не под версионным контролем.
- Легаси `electron/` + `src/` (React-прототип) всё ещё в репозитории; судьба — решить (вынести/удалить).
