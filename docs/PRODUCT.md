# Product Map — что откуда и что дальше

Документ отвечает на вопрос «что где»: какие функции островка пришли из апстрима, какие сделаны нами, что не реализовано и что ещё осталось «чужим» в идентичности. Основа для решения, что вырезать и что развивать.

Составлено по фактическому коду `desktop/OpenIsland` (~14.3k строк C#/XAML, 84 файла `.cs`) на текущий момент.

---

## 1. Происхождение

| Источник | Что это | Объём |
| :--- | :--- | :--- |
| **Апстрим** `mihailkotovski/DynamicIsland` | Готовый нативный островок на C# WPF: окно-оверлей, пружины, стекло, медиа, таймер, оформление, системный статус. Часть апстрим-виджетов вырезана (см. §2.5) | ~70% кода |
| **Наше** | Интеграция с локальным агентом OpenCode (список сессий, модели, промпты, стриминг, разрешения), хоткей, self-test, скрипты сборки, доки, логи/токен, апдейтер через GitHub Releases; мини-эквалайзер на любой системный звук; звук завершения задачи и тост о её окончании; история буфера обмена; мониторинг ПК (CPU/ядра/диск/RAM/GPU/сеть/температура); процессы и порты; быстрый запуск утилит | ~30% кода |

Практический вывод: апстрим — это «железо» островка (отрисовка, физика, медиа). Наш продукт — там, где появляется OpenCode и собственные виджеты. Лишние апстрим-модули уже вырезаны, «чужим» остаётся только внутреннее имя пространства имён.

## 2. Карта функций

Состояние: `ок` — работает, `частично` — есть оговорки, `план` — не реализовано.

### 2.1. Ядро островка (апстрим, `ок`)
Прозрачное topmost-окно без кражи фокуса, пружинная физика, стеклянные поверхности, морфинг капсулы, пузыри-уведомления, скрытие в полноэкранных приложениях, автозапуск.

- `MainWindow.xaml` (+ `.Shape.cs`, `.Transitions.cs`, `.Notices.cs`), `Spring.cs`, `Motion.cs`, `Liquid.cs`, `Goo.cs`, `Glass.cs`, `Squircle.cs`, `Aura.cs`, `StarField.cs`, `DotMatrix.cs`, `Visuals.cs`, `DrawingSurfaces.cs`, `DesktopComposition.cs`, `Native.cs`, `FrameLoop.cs`, `DelayedAction.cs`, `App.xaml(.cs)`.

### 2.2. Системный статус (апстрим, `ок`)
Громкость, заряд, индикатор наушников; краткие уведомления о подключении/потере сети и VPN, капсула «Не беспокоить».

- `MainWindow.Status.cs`, `MainWindow.Headset.cs`, `Headset.cs`, `AudioService.cs`, `CoreAudio.cs`, `NetworkService.cs`.

### 2.3. Медиаплеер (апстрим + наше, `ок`)
Системная медиасессия (GSMTC): обложка и палитра из неё, перемотка, прогресс, эквалайзер/спектр, источник трека. Для плееров без GSMTC (AIMP, Winamp, WACUP) — резервный канал через совместимое окно `Winamp v1.x`: состояние, позиция и длительность читаются скалярными `WM_USER`-селекторами, трек — из заголовка окна, команды идут через `WM_COMMAND`/`IPC_JUMPTOTIME`.

- `MediaService.cs`, `WinampIpc.cs`, `MainWindow.Media.cs`, `MainWindow.Seek.cs`, `Cover.cs`, `CoverPalette.cs`, `SourceApp.cs`, `PlayerBar.cs`, `Scrubber.cs`, `LineBar.cs`, `BandMeter.cs`, `Equalizer.cs`, `SpectrumService.cs`, `SpectrumAnalyzer.cs`, `SpectrumLevels.cs`, `Skip.cs`.
- Winamp/AIMP показывается, когда GSMTC не играет; играющий Winamp важнее приостановленной системной сессии, а приостановленный — только при отсутствии живой сессии GSMTC. Обложки у Winamp-совместимых плееров нет.

### 2.4. Мини-эквалайзер на любой звук — **наше**
Когда в системе есть звук, но активной медиасессии нет (видео в браузере, игра, голосовой чат), свёрнутый островок разворачивается в компактную капсулу `View.Sound` с одними полосками эквалайзера. Реагирует на **любой** системный вывод, а не только на треки GSMTC.

- `MainWindow.Media.cs` (`PollSound`, `SyncEq`, `AdvanceEq`), `AudioService.cs`/`CoreAudio.cs` (`IAudioMeterInformation` — дешёвый master peak, опрос 100 мс), `SpectrumService.cs` (тяжёлый WASAPI-loopback включается только пока остров реально виден: не в трее, не за полноэкранным приложением и не «спрятан на 5 секунд»).
- Порог детекта `SoundPeak = 0.004`, удержание `SoundHoldSeconds = 2.2`. Полоски рисует тот же `Equalizer`, что и в плеере.
- Если в это время занят агент OpenCode, полоски не пропадают: они живут и в компактной капсуле агента (`View.OpenCode`) — справа от статуса, пока есть системный звук; таймер задачи сдвигается левее. Без звука капсула агента остаётся обычной (статус + таймер).

### 2.5. Удалённые апстрим-модули — **вырезано**
Вырезаны как «чужие»: тексты песен (5–6 внешних API, строка у курсора и эффекты), запись экрана через OBS (WebSocket), полка файлов (drag & drop), погода и геолокация, QR-код (скан и показ, пакет `ZXing.Net`).

- Ушли файлы: `LyricsService.cs`, `LyricsCatalogues.cs`, `MainWindow.Lyrics.cs`, `MainWindow.PointerLyric.cs`, `Lyric.cs`, `CompactLyric.cs`, `PointerLyric.cs`, `Parting.cs`, `LyricPreview.cs`, `Shimmer.cs`, `ObsService.cs`, `MainWindow.Record.cs`, `Shelf.cs`, `ShelfTile.cs`, `MainWindow.Shelf.cs`, `WeatherService.cs`, `MainWindow.Weather.cs`, `QrReader.cs`, `AreaPicker.cs`, `MainWindow.Qr.cs` и пакет `ZXing.Net`. `StayOnTop()` переехал из удалённого файла в `MainWindow.Shape.cs`.

**Пересмотр (16.11.2026):** полка файлов, погода, QR и тексты песен снова лежат в бэклоге как кандидаты — но уже не как унаследованные апстрим-модули, а как собственные нативные реализации, если их оправдывает спрос (см. §7). Решение по каждому принимается отдельно; ничего из перечисленного не возвращается автоматически.

### 2.6. Таймер / будильник (апстрим, `ок`)
Преcеты 5–45 мин, пауза, кольцо прогресса, звонок и пульс при завершении.

- `MainWindow.Timer.cs`, `Countdown.cs`, `Alarm.cs`, `Ring.cs`.

### 2.7. Оформление и настройки (апстрим, `ок`)
Страницы меню: настройки и оформление. Масштаб, отступ, стекло, фон (матрица/звёзды), акцент, вид эквалайзера, отклик кнопок. Всё хранится в реестре.

- `MainWindow.Menu.cs`, `Settings.cs`, `Toggle.cs`, `Segments.cs`, `RowList.cs`, `BackdropPreview.cs`, `Icon.cs`, `Digits.cs`, `Puddle.cs`, `ChipCorners.cs`.

### 2.8. Обновление — **наше, `ок`**
Страница «Обновление»: версия, changelog, скачивание exe, сверка хеша, автоперезапуск.

- `Updater.cs`.
- Репозиторий релизов задаётся `const string Repository = "mmmatveyz/OpenIsland"`: апдейтер читает `releases/latest`, скачивает ассет `OpenIsland.exe` и сверяет `sha256`-дайджест из ответа GitHub перед подменой файла.
- Репозиторий публичный: **[github.com/mmmatveyz/OpenIsland](https://github.com/mmmatveyz/OpenIsland)**. Первый релиз собирается workflow `.github/workflows/release.yml` по тегу `v*`.
- В релиз публикуются два ассета: portable `OpenIsland.exe` и установщик `OpenIslandSetup-<версия>.exe` (Inno Setup, per-user установка в `%LOCALAPPDATA%\Programs\OpenIsland`). Скрипт — `installer/OpenIsland.iss`, сборка — `scripts\build.ps1 -Installer`.

### 2.9. OpenCode AI Hub — **наше**
REST + SSE клиент, список сессий, прокручиваемая история сообщений с догрузкой (40 на страницу, до 400 в памяти), модели, промпты, живой стриминг ответа, разрешения, горячая клавиша, self-test, звук завершения задачи и тост при завершении длинной задачи.

- `OpenCodeService` — partial-класс: ядро (`OpenCodeService.cs`) плюс `OpenCodeService.Discovery/Http/Sessions/Commands/Stream/Diff.cs`. Рядом — `MainWindow.OpenCode.cs`, `SessionList.cs`, `MarkdownText.cs`, `OpenCodeSelfTest.cs`, `Chime.cs`, XAML-секция OpenCode, `Native.cs` (хоткей + активация). История выбранной сессии показывает последние 40 сообщений с живым обновлением ответа и догружает более ранние по кнопке «Показать раньше» или прокруткой вверх (курсор API, потолок 400 сообщений); ходы агента без текста (только вызовы инструментов) показываются компактными строками действий, а не пропадают. Разбор понимает формат V2 (роль в `type`, текст ответа в `content`, текст пользователя в `text`) и легаси `role`/`parts`. Markdown-разметка (`**жирный**`, код, ссылки, списки) убирается для отображения — чистая логика в `MarkdownText.cs`.
- Список сессий: панель-оверлей внутри карточки (клик по заголовку сессии); строки отсортированы по времени последнего обновления (свежие сверху), показывают папку и относительное время, точка отмечает текущую (индиго) и работающую (оранжевая) сессию. При 8+ сессиях появляется поиск по названию и папке. Чистая логика (порядок/фильтр/имя папки/относительное время) — в `SessionList.cs`.
- Изменения агента: кнопка «Изменения» открывает оверлей со списком файлов (`added`/`modified`/`deleted`, `+`/`−`); клик по файлу раскрывает unified-патч с подсветкой добавленных и удалённых строк. Данные (`GET /api/session/{id}/diff`) грузятся по требованию, а не по таймеру; патч ограничен `MaxPatchLines`/`MaxPatchLineLength`, чтобы 100-килобайтные диффы не тормозили UI. Разбор — `OpenCodeService.Diff.cs`.
- Звук завершения: на переходе агента `busy → idle` (при живом соединении) играет `Assets/staplebops-01.mp3` — тот же звук, что у самого OpenCode (лицензия MIT), если включена настройка `Settings.TaskChime` (по умолчанию включена). Файл **встроен в exe** как WPF-ресурс (`Resource`) и при первом использовании выгружается в `%LOCALAPPDATA%\OpenIsland\staplebops-01.mp3` (MediaPlayer играет только с диска). Так звук доезжает и в portable-exe, и после автообновления, где рядом с exe других файлов нет.
- Тост при завершении задачи: если агент работал дольше `TaskToastAfter` (15 с), вместе со звуком показывается Windows-уведомление («Задача OpenCode завершена») через иконку трея (`Shell_NotifyIcon` + `NIF_INFO`) — без новых зависимостей. Выключается в настройках (`Settings.TaskToast`).
- Компактная капсула статуса (`View.OpenCode`, 246×34): «◈ Агент: …» слева и живой эквалайзер справа, пока в системе есть звук; эквалайзер общий с плеером (`Shared.Eq`), поэтому не пропадает во время работы агента.
- Офлайн-состояние: если демон не запущен, карточка не притворяется рабочей — заголовок «OpenCode не запущен», навигация по сессиям/моделям, ввод и «Отправить» отключаются (приглушены), а акцентная кнопка «Запустить OpenCode» поднимает приложение. После старта демона островок подключается сам (опрос раз в 2 с, обнаружение — раз в 15 с). Клик по островку в офлайне открывает меню, а не мёртвую карточку.
- Состояние: `ок`. Роадмап-хвосты — в §4.

### 2.10. История буфера обмена — **наше, `ок`**
Карточка «Буфер обмена» из меню: последние 30 фрагментов текста с временем («сейчас», «5 мин»), по клику фрагмент возвращается в буфер, кнопка «Очистить». Захват идёт по `WM_CLIPBOARDUPDATE` (`Native.WatchClipboard`), поэтому история копится, даже когда карточка закрыта.

- `ClipboardService.cs` (кольцевая история в памяти), `MainWindow.Clipboard.cs`, `Native.cs` (`WatchClipboard`, `WM_CLIPBOARDUPDATE`), XAML-карточка `ClipboardView`, пункт меню со счётчиком.
- **Приватность**: история живёт только в памяти процесса, ничего не пишется на диск и в логи; выключатель `Settings.Clipboard` (по умолчанию включён) очищает историю при выключении.

### 2.11. Мониторинг ПК — **наше, `ок`**
Карточка «Мониторинг ПК»: CPU (общая нагрузка и полоски по ядрам, до 16 — дальше ядра усредняются в группы), память (занято/всего и %), видеокарта, диск (активность `% Disk Time` и свободное место на системном диске), сеть (↓/↑ в реальном времени) и температура, с полосками-индикаторами; недоступные GPU/температура/диск показываются как «н/д».

- `PerfService.cs`, `PerfMath.cs` (сжатие загрузки ядер до 16 столбиков), `MainWindow.Perf.cs`, XAML-карточка `PerfView`, пункт меню с текущим CPU%.
- **Дёшево в фоне**: опрос идёт только пока карточка открыта (`SetActive(target == View.Perf, PerfView.IsMouseOver)`), считается на фоновом потоке; под курсором интервал 1 с, иначе 3 с. CPU — `GetSystemTimes`, ядра и диск — PDH (`PdhAddEnglishCounter`, локаль-независимо), память — `GlobalMemoryStatusEx`, сеть — `NetworkInterface`, GPU — PDH `\GPU Engine(*)\Utilization Percentage` (раз в 2 с, берётся максимум по движкам), температура — WMI `MSAcpi_ThermalZoneTemperature` (раз в 5 с). Недоступные значения показываются как «н/д» (частая картина для температуры на десктопах).

### 2.12. Процессы и порты — **наше, `ок`**

Карточка «Процессы и порты» из меню: запущенные dev-инструменты (Node, Python, PHP, Ruby, Go, Docker, dotnet, Java и др.) и владельцы слушающих локальных портов, с завершением процесса в два шага.

- `DevProcesses.cs` (чистая логика: список известных/системных имён, определение версии инструмента, фильтр, сортировка, формат портов и памяти), `PortScanner.cs` (владельцы портов через IP Helper API — `GetExtendedTcpTable`/`GetExtendedUdpTable`, без `netstat`), `DevProcessService.cs` (фоновый опрос, `Kill`, `Changed`), `MainWindow.Processes.cs`, XAML-карточка `ProcessesView`, пункт меню «Процессы и порты».
- Два режима: **«Dev»** (по умолчанию — только известные dev-инструменты) и **«Все»** (плюс любой процесс, занимающий порт, кроме системных). Состояние режима между открытиями не сохраняется. Процессы, занявшие порт, но с неизвестным именем, видны только в режиме «Все»; системные имена исключены всегда.
- Строка показывает имя и версию, память, идентификатор процесса и порты; по клику открывается панель подтверждения с кнопками «Отмена»/«Завершить» (случайное завершение исключено). Высота карточки подстраивается под число строк (минимум 250, максимум 470) и замораживается на время подтверждения, чтобы кнопка не «уезжала».
- **Дёшево в фоне**: опрос идёт только пока карточка открыта (интервал 2,5 с); закрытая карточка не нагружает систему.
- Тесты: `tests/OpenIsland.Tests/DevProcessesTests.cs` — фильтр, версии инструментов, `Normalize`, сортировка, форматирование портов/памяти и живой `PortScanner` через `TcpListener`.

### 2.13. Быстрый запуск — **наше, `ок`**

Карточка «Быстрый запуск» из меню: системные утилиты одним кликом и свои программы. После запуска остров сворачивается, поэтому карточка работает как мини-лаунчер, не отвлекая от задачи.

- Системные плитки: Проводник, Терминал (Windows Terminal, если установлен, иначе PowerShell), Калькулятор, Блокнот, Диспетчер задач, Параметры, Панель управления и Ножницы. Запуск идёт через оболочку Windows (`UseShellExecute`), поэтому работают и обычные `exe`, и системные URI (`ms-settings:`, `ms-screenclip:`).
- Свои программы: `.exe`, `.lnk`, `.bat`, `.cmd` добавляются кнопкой «+ .exe» через системный диалог выбора файла, удаляются кнопкой «×» в строке. Список хранится в реестре (`Settings.QuickLaunch`) строкой `Имя|Путь|Аргументы` на команду; папка файла становится рабочим каталогом.
- Логика вынесена в `QuickActions.cs` (разбор/сборка списка, проверка типа файла, существование пути, `ProcessStartInfo`), UI — `MainWindow.QuickLaunch.cs`, XAML-карточка `QuickLaunchView`, пункт меню «Быстрый запуск».
- Тесты: `tests/OpenIsland.Tests/QuickActionsTests.cs` — разбор и round-trip списка, аргументы с `|`, фильтр расширений, проверка существования файла и параметры запуска.
- **Дёшево в фоне**: карточка не опрашивает систему, плитки строятся один раз, список читается из реестра при открытии/изменении.

## 7. Внешний ориентир: Island (`exuupery/island`) — сравнение, без копирования

Разбор чужого проекта, найденного 16.11.2026: [github.com/exuupery/island](https://github.com/exuupery/island) (демо-сайт — `islandapp.pro`). Зафиксировано как источник идей для UI, а не как источник кода.

**Что это.** Коммерческий Dynamic Island для Windows 10/11: «жидкая» чёрная пилюля под верхней кромкой экрана, которая раскрывается в панель с плеером, полкой файлов, буфером, инструментами для текста, чатом с ИИ, скриншотами и командной строкой. 162★, 7 форков, ~20 коммитов, открытые Issues ведутся; актуальный релиз — **1.2.10 (09.11.2026)**.

**Правовой статус: код брать нельзя.** В репозитории нет исходников — только `README.md`, `docs/img/`, `social/` и `app-icon.svg`; файла лицензии тоже нет. Это витрина закрытого продукта (Island Pro, 399 ₽ разово, офлайн-проверка ключа). Разрешённый вывод из разбора — идеи, названия подходов и визуальные приёмы; любые реализации пишем сами.

**Стек.** Судя по ассету релиза `Island_x.y.z_x64-setup.exe` и заметке в changelog «обновлена библиотека проверки сертификатов» — Tauri (Rust + WebView2), то есть веб-UI поверх нативного хоста. Наш WPF выигрывает по памяти (нет WebView2-процессов) и по глубине интеграции с OpenCode; их сильная сторона — ширина фич и отделка визуала.

**Пересечение и разница.** Важное для нас: в 1.2.10 они добавили статус `opencode` в пилюлю «как Claude Code и Codex» — то есть заходят в нашу нишу, но у нас это ядро продукта (SSE-стриминг и разрешения), а у них Pro-фича поверх чужих хуков. Заодно у них есть поддержка плееров, которые не сообщают о себе Windows (AIMP, Winamp); мы закрыли этот пробел в v1.2.6 через совместимое окно `Winamp v1.x` (`WinampIpc.cs`).
