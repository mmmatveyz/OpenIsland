# Архитектура OpenIsland

Документ описывает устройство нативного приложения `desktop/OpenIsland` (C# WPF, .NET 8), оконный менеджмент, рендеринг островка, сервисы виджетов и интеграцию с OpenCode.

---

## 1. Общая схема системы

```text
+--------------------------------------------------------------------------+
|                               WINDOWS 10/11                              |
+--------------------------------------------------------------------------+
      │ Win32 / DWM / GSMTC        │ Media, power, network      │ OpenCode daemon
      ▼                            ▼                            ▼
+---------------------+   +----------------------+   +-------------------------+
| Native.cs           |   | MediaService /       |   | OpenCodeService.cs      |
| topmost, toolwindow |   | AudioService /       |   | REST + SSE + pairing    |
| fullscreen checks   |   | NetworkService / ... |   | DPAPI token storage     |
+---------------------+   +----------------------+   +-------------------------+
      │                            │                            │
      └──────────────┬─────────────┴──────────────┬─────────────┘
                     ▼                            ▼
+--------------------------------------------------------------------------+
|                    MainWindow (WPF, UI thread)                           |
|                                                                          |
|  - View/Panel routing: TargetView(), ShowPanel(), WorkArea()             |
|  - Spring physics: Spring.cs + MainWindow.Shape.cs                       |
|  - Custom visuals: DrawingVisual widgets (spectrum, equ, goo, glass)     |
|  - Modules: MainWindow.Media.cs, .Timer.cs, .Status.cs, .Menu.cs, ...    |
|  - OpenCode UI: MainWindow.OpenCode.cs                                   |
+--------------------------------------------------------------------------+
                     │
                     ▼
+--------------------------------------------------------------------------+
|       Transparent always-on-top overlay window (HostWidth x HostHeight)  |
|       Rounded "island" pill, morphs between compact and expanded states  |
+--------------------------------------------------------------------------+
```

Приложение однопроцессное. Сетевые и фоновые операции выполняются асинхронно, UI обновляется в потоке диспетчера WPF.

## 2. Окно и оконный менеджмент

### 2.1. Параметры окна

`MainWindow.xaml`:

```xml
<Window WindowStyle="None" AllowsTransparency="True" Background="Transparent"
        ShowInTaskbar="False" ShowActivated="False" Topmost="True"
        ResizeMode="NoResize" Width="620" Height="592">
```

- Окно-хост имеет фиксированный размер `620 × 592` (`HostWidth`/`HostHeight` в `MainWindow.xaml.cs`), позиционируется по центру верхней кромки рабочего стола.
- `AllowsTransparency` + прозрачный фон: клики получают только реальные элементы островка; прозрачные области не перехватывают мышь.
- `Native.cs` дополнительно помечает окно как `WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`, чтобы оно не появлялось в Alt+Tab и не забирало фокус у активного приложения. Для стеклянных поверхностей используется расширенный стиль `WS_EX_NOREDIRECTIONBITMAP | WS_EX_LAYERED`.
- `StayOnTop()` периодически возвращает окно наверх, не активируя его (`SWP_NOACTIVATE`).

### 2.2. Позиционирование и полноэкранный режим

- Островок выравнивается по центру рабочей области; отступ сверху задаётся настройкой `Gap`, масштаб — `Scale`.
- При активном полноэкранном приложении или игре (проверка через Win32 foreground window и его стилей) островок скрывается, если включена настройка `HideFullscreen`.
- Окно остаётся поверх всех окон (`Topmost`), но не мешает играм в полноэкранном режиме.

### 2.3. Мышь и интерактивность

- `MainWindow.Pointer.cs`: наведение, клик, drag, правый клик (контекстное меню), прокрутка.
- Пружины (`Spring.cs`) обеспечивают плавное «дыхание» и морфинг без резких скачков.
- Наведение на капсулу включает компактное превью (обложка, прогресс, эквалайзер) и увеличивает кликабельную область точечно, не раздувая окно.

### 2.4. Глобальные хоткеи

`RegisterHotKey` (Win32) регистрирует при инициализации окна две комбинации, и обе разбирает хук `HwndSource` (`OnHotkeyMessage`):

- **Ctrl+Alt+O** — карточка OpenCode: если она открыта, сворачивается; иначе открывается `Panel.OpenCode`, окно поднимается наверх, фокус переводится в поле задачи.
- **Ctrl+Alt+I** — сквозной режим (§2.6).

Обе освобождаются в `OnClosed`. Если комбинация занята другой программой, приложение продолжает работать, а в лог пишется предупреждение. Ctrl+Alt+Space не используется, так как часто занят системными утилитами.

### 2.5. Активация окна и авто-сворачивание

- По умолчанию окно неактивируемо (`WS_EX_NOACTIVATE`), чтобы не отбирать фокус. Перед вводом текста (поле задачи OpenCode) `EnterTextEntry()` запоминает текущее активное окно, включает активацию (`MakeActivatable(true)`), поднимает и активирует островок; `LeaveTextEntry()` снимает фокус, возвращает передний план прежнему окну и снова запрещает активацию.
- Раскрытая панель сворачивается сама по таймеру `_collapseTimeout`: `CollapseDelay` (≈0.55 с) для обычных панелей и `LongCollapseDelay` (2.5 с) для `Panel.OpenCode`, чтобы успеть прочитать текст или начать ввод. Наведение мыши отменяет таймер, уход курсора — перезапускает, набор в поле задачи (`OpenCodePromptBox_TextChanged`) продлевает его.
- `Collapse()` не сворачивает панель, пока курсор на островке. `CollapseNow()` сворачивает немедленно: по повторному нажатию хоткея и при потере активации (`OnDeactivated`, например клик по другому окну).

### 2.6. Сквозной режим (click-through)

Флаг `WS_EX_TRANSPARENT` (через `Native.SetClickThrough`) делает окно невидимым для мыши: клики и наведение уходят приложению под островом, при этом остров остаётся видимым и продолжает обновляться (медиа, таймер, статус агента, уведомления).

- Включается и выключается **Ctrl+Alt+I** (§2.4), пунктом «Сквозной режим» в меню трея (галочка показывает текущее состояние) или аргументом запуска `--clickthrough`. Выбор сохраняется в `Settings.ClickThrough`, поэтому режим переживает перезапуск; аргумент только форсирует его на текущий сеанс без записи в реестр.
- Включение снимает «залипшее» состояние указателя: `ApplyClickThrough` сбрасывает `_hovered`, отпускает захват мыши и немедленно сворачивает панель. `RefreshHover` в этом режиме не перечитывает `IsMouseOver`, потому что окно больше не получает мышь.
- `RevealSettings()` из трея выключает режим перед показом настроек — иначе по ним нельзя было бы кликнуть.

## 3. Формы островка и рендеринг

### 3.1. View и Panel

Состояния UI описаны двумя перечислениями в `MainWindow.xaml.cs`:

- `View` — конкретный визуальный экран (`Idle`, `Sound`, `Media`, `Volume`, `TimerBig`, `Menu`, `Settings`, `OpenCodeBig`, `Perf`, `Clipboard`, `Processes`, `QuickLaunch`, ...).
- `Panel` — логическая раскрытая панель (`Player`, `Timer`, `Menu`, `Settings`, `OpenCode`, `Perf`, `Clipboard`, `Processes`, `QuickLaunch`, ...).

`TargetView()` выбирает экран по приоритету: принудительный view → активная панель → активный агент OpenCode → медиа → звук (`_sounding`) → таймер → idle. `ShowPanel()`/`SelectPanel()` переключают панель и анимируют переход.

### 3.2. Геометрия капсулы

`PillShapes` задаёт базовые `Width`, `Height`, `Radius` для каждого `View`. Динамические размеры (например, `MediaBig` с крупной обложкой или `Update`) вычисляются в `ShapeOf()`.

`MainWindow.Shape.cs`:

- четыре пружины `_width`, `_height`, `_radius`, `_userScale` плавно интерполируют форму;
- тень, блики и «жидкое» стекло (`Liquid.cs`, `Goo.cs`, `Glass.cs`) рисуются вручную;
- пузырьки уведомлений (таймер, громкость, наушники) анимируются отдельными пружинами; события выстраиваются в очередь, чтобы не перебивать друг друга;
- `DrawingSurfaces.cs` и `Visuals.cs` инкапсулируют недорогие `DrawingVisual`-поверхности.

### 3.4. Живой силуэт: кромка по спектру и дыхание — **прототип сделан, отложено**

> **Итог прототипа (v1.2.0).** Дизайн ниже был реализован целиком (`EdgeWave.cs`, волнистая нижняя кромка в `Squircle`/`Goo`, `SpectrumLevels.Revision`/`FollowPeak`, `AdvanceEdge` в цикле `_eqLoop`, настройки `EdgeWave`/`EdgeWaveAmplitude`/`Lively`) и проверен снимками при обоих направлениях гребней. Результат **не устроил**: простая полилиния из 16 полос на компактной пилюле читается как «погрызенный снизу край», а не как жидкий силуэт Island. Код откачен, фича снята с v1.2.0 и перенесена в R&D: нужен настоящий «жидкий» рендер (безье-сглаживание, наружные всплески, а возможно и метаболы), а не волна поверх уже существующего squircle. Раздел сохранён как проработанный дизайн на будущее; «дыхание/провис» тоже отложено вместе с ним. Открытые вопросы ниже остаются неотвеченными.

**Идея** (из бэклога по мотивам Island, `docs/PRODUCT.md` §7.2): силуэт пилюли перестаёт быть статичным squircle. Затрагивает `Goo.cs`, `MainWindow.Shape.cs`, `SpectrumLevels.cs` (+ `EdgeWave.cs`), настройки и меню. Ниже — дизайн, как он планировался.

**Что уже есть и переиспользуется.** `SpectrumLevels` даёт 16 сглаженных полос с attack/release и методом `At(share)` для интерполяции по горизонтали; `AudioService` умеет отдавать дешёвый master peak без WASAPI-loopback. `Goo.DrawBody` обводит тело геометрией `_edge`, а цвет обода анимирует `Body.Tint` в `SyncRim` — значит, волнистая кромка автоматически получит тинт обложки/акцента и вспышку `StartFlashing`, без отдельной отрисовки.

**Механика кромки.** Новый `EdgeWave.cs` — чистая функция: строит один `StreamGeometry` силуэта, у которого нижняя сторона заменена на `Bands` квадратичных сегментов с высотой `SpectrumLevels.At(x)`. Один путь за кадр вместо `Geometry.Combine` на каждый зуб — это принципиально, потому что `Geometry.Combine` дорогой и его нельзя звать десятки раз в кадр.

- **Куда направлены зубцы.** Остров обрезан: `Host.Clip = Shared.Clip = Shadow.Data = Squircle.Of(pill, r)`, плюс `Shadow.Clip` и вырез стекла `Glass.Cut`. Поэтому гребни направляем **внутрь** пилюли от нижней линии (базовая линия — низ пилюли, волна идёт вверх). Силуэт читается как зубчатый низ, и ничего не срезается. Вариант «шипы наружу», как у Island, требует расширять `_clipRect` на амплитуду и пересчитывать `Shadow.Clip`/`Glass.Cut` — это дороже и хрупче, поэтому он остаётся опцией B и решается отдельно.
- **Амплитуда** — начальное значение 10 px, диапазон 0–20, настройка `Settings.EdgeWaveAmplitude`; плавно поднимается от 0 при старте звука и опускается к 0 при тишине (та же экспоненциальная сглаженность, что в `SpectrumLevels.Follow`), чтобы кромка «входила» и «выходила», а не щёлкала.
- **Инвалидация.** `Body.SetShape` рано выходит, если `pill`, `radius` и `bubble` не изменились, поэтому в него добавляется ревизия кромки (например, счётчик изменившихся полос) — иначе при неподвижной геометрии волна не перерисуется.
- **Тинт.** Цвет берётся из уже готового `AccentColor`/палитры обложки (`CoverPalette`); отдельная заливка зубцам не нужна, работает обводка `_edge`.

**Дыхание и провис.** В покое петля `_shapeLoop` останавливается (`EndMorph`), остров замирает. Добавляем режим «живой»: пока окно видимо, цикл продолжается на пониженной частоте и подаёт в `UpdateTargets` малую синусоидальную добавку к `_height`/`_radius`, а при отсутствии курсора над островом дольше нескольких секунд — медленный «провис» (высота вниз на ~1.5 px, лёгкая сплюснутость), как у аналога.

**Бюджет и правила §4.2.** Живой режим выключается полностью, когда: окно скрыто, остров спрятан за краем (`_hiddenByFullscreen`, `_sentAway`), открыто полноэкранное приложение, идёт морфинг или drag. Частота живого режима — около 20 кадров в секунду (не 60), амплитуда дыхания — доли пикселя; кромка тикает только при реальном звуке. Тяжёлый `SpectrumService` (WASAPI-loopback) продолжает включаться лишь по видимости, как сейчас; при отсутствии трека кромка опирается на дешёвый peak из `AudioService`.

**Проверка.** `EdgeWave` — чистые функции, значит покрывается юнит-тестами (число сегментов равно `Bands`, при нулевой амплитуде низ ровный, все точки остаются в границах пилюли). Дальше — сборка с 0 предупреждений, `scripts\build.ps1 -Test` и замер фонового CPU до/после (цель — те же 0–1 %). Визуальный результат смотреть через `--view …` и замеры профилировщика WPF, потому что корректность отрисовки тестами не проверяется.

**Новые настройки** (реестр, страница оформления в `MainWindow.Menu.cs`): `EdgeWave` (вкл/выкл, по умолчанию включено), `EdgeWaveAmplitude` (0–20 px), `Lively` (дыхание и провис, по умолчанию включено).

**Открытые вопросы.** Нужен ли вариант с шипами наружу (опция B) и не мешает ли он тени и стеклу; стоит ли отдавать амплитуду кромки на быстрые частоты отдельно (сейчас полосы уже разложены по частотам); как ведёт себя кромка в капсуле `View.Sound` без трека — там источник один peak, а не спектр.

## 4. Интеграция с OpenCode

### 4.1. Обнаружение и авторизация

`OpenCodeService` (partial-класс; ядро — в `OpenCodeService.cs`, остальное разнесено по `OpenCodeService.Discovery/Http/Sessions/Commands/Stream.cs`):

1. Находит CLI `opencode-cli.exe` в `%APPDATA%\ai.opencode.desktop\cli\*`, `%LOCALAPPDATA%\Programs\@opencode-aidesktop\resources` или `PATH`.
2. Выполняет `opencode service status`, извлекает URL демона (обычно `http://127.0.0.1:28894`) и проверяет доступность `/api/info`. Если порт сменился — сервис находится заново.
3. При отсутствии токена запускает `opencode pair`, забирает одноразовую ссылку, получает токен и сохраняет его через DPAPI (`%LOCALAPPDATA%\OpenIsland\opencode-token.bin`). При `401` пейринг повторяется автоматически.
4. Токен передаётся в заголовке `Authorization: Basic base64("opencode:<token>")`.

### 4.2. REST API

| Назначение | Метод и путь |
| :--- | :--- |
| Проверка сервиса | `GET /api/info` |
| Список сессий | `GET /api/session` |
| Активные сессии | `GET /api/session/active` |
| Список моделей | `GET /api/model` |
| Создание сессии | `POST /api/session` (`title`, `location.directory`, `model`) |
| Удаление сессии | `DELETE /api/session/{id}` |
| Отправка задачи | `POST /api/session/{id}/prompt` (`{"text": "..."}`) |
| Смена модели | `POST /api/session/{id}/model` (`{"model": {"id", "providerID"}}`) |
| Остановка агента | `POST /api/session/{id}/interrupt` |
| Сообщения сессии | `GET /api/session/{id}/message?limit=40&order=desc` — страница и курсоры `cursor.previous` / `cursor.next`; более ранняя страница — `?limit=40&cursor=<next>` (без `order`). Роль в `type`, текст в `content`; поддерживается и легаси `role`/`info.role` + `parts` |
| Изменения агента | `GET /api/session/{id}/diff` (`{file, patch, additions, deletions, status}`; грузится по требованию) |
| Разрешения | `GET /api/session/{id}/permission`, `POST /api/session/{id}/permission/{requestID}/reply` (`decision`: `once` / `always` / `reject`) |
| Поток событий | `GET /api/event` (SSE) |

### 4.3. SSE и состояние

Поток `/api/event` читается построчно; кадры `data: {json}` разбираются в `HandleEvent()`. Ключевые события:

- `session.status` — `idle` / `running` / `retry` (индикатор и текст статуса);
- `session.execution.started/succeeded/failed` — старт и завершение задачи, ошибки;
- `session.text.started/delta/ended` — живой текст ответа (с ограничением буфера);
- `permission.asked/replied` — запросы доступа агента и их закрытие;
- `session.model.selected` — смена модели;
- `session.created/deleted/renamed` — обновление списка сессий.

Параллельно раз в 2 секунды выполняется `RefreshAsync()`: обновляет сессии, модели, активную сессию и разрешения. Это страховка на случай разрыва SSE (поток переподключается через 3 секунды). Уведомления UI троттлятся (~120 мс) и схлопываются, чтобы не перерисовывать островок на каждый токен.

### 4.4. UI OpenCode AI Hub

`MainWindow.OpenCode.cs` + блок `OpenCodeBigView` в XAML (панель шириной 380):

- заголовок-сессия: клик раскрывает оверлей со списком сессий внутри карточки (свежие сверху, папка + относительное время, точка текущей/работающей сессии; поиск при 8+ сессиях), клик по строке выбирает сессию и закрывает панель; кнопка «×» в заголовке удаляет текущую сессию (подтверждение вторым кликом). Логика списка вынесена в `SessionList.cs` (чистые функции: порядок, фильтр, имя папки, относительное время);
- выбор модели (`‹ МОДЕЛЬ ›`);
- поле ввода задачи (`Enter` — отправить);
- блок ответа агента (живой текст и финальный ответ из истории сообщений). Текст выводится простым `TextBlock`, поэтому markdown-разметка ответа снимается через `MarkdownText.ToPlainText` (свойство `OpenCodeMessage.DisplayText`); сообщения пользователя берутся из поля `text`/`metadata.displayText` ответа V2, а вложения (`files`, base64) не показываются и не сохраняются. Ходы ассистента без текста (только `reasoning`/`tool`) не теряются: они превращаются в одну компактную строку «⚙ shell: … · read: …» (моноширинный шрифт, обрезка с многоточием, полный текст в подсказке). История листается страницами по 40 (`cursor.next` в порядке `desc` ведёт вглубь) — кнопкой «Показать раньше» и прокруткой вверх; в памяти держится до 400 сообщений, догрузка старых страниц не отбрасывает только что полученное;
- оверлей «Изменения» (`OpenCodeDiffOverlay`): список изменённых агентом файлов с `+`/`−`, раскрытие unified-патча по клику, кнопка обновления. `RefreshDiffAsync` вызывается только по требованию (открытие оверлея, ручное обновление, завершение задачи при открытом оверлее), а не в общем опросе;
- панель разрешений «Разрешить / Отклонить»;
- кнопка «Стоп» для прерывания выполнения;
- звук завершения: при переходе агента из «работает» в «готово» играет `Chime` (звук OpenCode, MIT), если включена настройка `Settings.TaskChime` (по умолчанию включена). MP3 встроен в exe (`Resource`) и один раз выгружается в `%LOCALAPPDATA%\OpenIsland\staplebops-01.mp3`, потому что `MediaPlayer` умеет открывать только файл на диске;
- тост о завершении: если задача выполнялась дольше `TaskToastAfter` (15 с), вместе со звуком показывается уведомление Windows через иконку трея (`Shell_NotifyIcon` + `NIF_INFO`, `Native.ShowBalloon`) с флагом `NIIF_NOSOUND` — системный звук Windows подавлен, чтобы не дублировать `Chime`; выключается настройкой `Settings.TaskToast`;
- транзиентная надпись под заголовком (`ShowOpenCodeNotice`, гаснет через 4 с) подтверждает удаление сессии и другой выбор.

Статусы сбоя API переводятся в человеческий текст в `DescribeFailure`: `0` → «OpenCode не отвечает» (или «нет связи с OpenCode»), `401` → «требуется авторизация», `404` → «сессия не найдена», `409` → «сессия занята».

Компактная капсула `View.OpenCode` показывает часы, состояние агента и длительность задачи; при работе агента островок автоматически переходит в это состояние. Если при этом играет музыка, клик по свёрнутому островку открывает плеер, а карточка агента остаётся доступной через **Ctrl+Alt+O** и меню.

Офлайн-состояние: без соединения заголовок карточки — «OpenCode не запущен», навигация по сессиям/моделям, поле ввода и «Отправить» приглушены и отключены, кнопка запуска выделена акцентом и поднимает OpenCode Desktop. Клик по островку, когда ничего не играет и OpenCode не подключён, открывает меню (`Panel.Menu`), а не пустую карточку агента. После старта демона состояние возвращается само (опрос раз в 2 с, обнаружение — раз в 15 с).

### 4.5. Диагностика

`--selftest` (`OpenCodeSelfTest.cs`) в headless-режиме проверяет: доступность демона, непустые списки сессий и моделей, создание временной сессии, смену модели, отправку промпта и получение ответа. Сессия удаляется после теста. Результат пишется в `%LOCALAPPDATA%\OpenIsland\logs\app.log`.

## 5. Потоки и производительность

- Все сетевые вызовы — `async`/`await`; UI обновляется через `Dispatcher.BeginInvoke`.
- `OpenCodeService` использует отдельный `HttpClient` с бесконечным таймаутом для SSE и обычный клиент с таймаутом 10 с для REST.
- Опрос OpenCode — раз в 2 секунды; при отсутствии соединения интервал сохраняется, но discovery выполняется не чаще раза в 15 секунд.
- Тяжёлые визуальные эффекты включаются только для видимых состояний; фоновые таймеры останавливаются при скрытии островка.
- `PerfService` опрашивается **только пока открыта карточка мониторинга**: `UpdateView` вызывает `SetActive(target == View.Perf, PerfView.IsMouseOver)`, и пока карточка закрыта, таймер спит (`Timeout.Infinite`). Под курсором интервал — 1 с, стоит увести мышь — 3 с (`FastIntervalMs`/`SlowIntervalMs`). Ядра и диск читаются PDH-счётчиками (`PdhAddEnglishCounter`, локаль-независимо), загрузка ядер сжимается до 16 столбиков в `PerfMath.AggregateCores`. Замеры идут на фоновом потоке, готовые значения приходят в UI через `Dispatcher`.
- Захват буфера обмена — это событие `WM_CLIPBOARDUPDATE`, а не опрос: окно получает сообщение из системы (`Native.WatchClipboard`) и только тогда читает текст. Подписка снимается в `OnClosed`.
- `DevProcessService` опрашивается **только пока открыта карточка «Процессы и порты»** (`SetActive(target == View.Processes)`, интервал 2,5 с); список портов читается через IP Helper API, завершение процесса — `Process.Kill`, сервис освобождается в `OnClosed`.
- `WeatherService` обращается к открытым API только по требованию (открытие карточки или кнопка «Обновить»), кэширует погоду на 25 минут и геокодирует запросы городов; в свёрнутом состоянии никаких сетевых вызовов погоды не происходит.
- `SoundFx` синтезирует короткие 16-битные моно PCM-сэмплы в памяти один раз при запуске и воспроизводит их через `System.Media.SoundPlayer(MemoryStream)` с нулевой задержкой и без блокировки UI-потока.
- Логирование (`App.LogDebug`) — в `%LOCALAPPDATA%\OpenIsland\logs\app.log` с ротацией при 1 МБ; в релизе — только значимые события и ошибки.

## 6. Безопасность

1. **Токен OpenCode** хранится только в зашифрованном виде (DPAPI, `CurrentUser`). Plaintext-файл старого формата мигрируется и удаляется.
2. **Пейринг** выполняется через официальный `opencode pair`; ссылка одноразовая и живёт 5 минут.
3. **Логи** не содержат токенов, cookies и приватного содержимого; ошибки API логируются в усечённом виде.
4. **Сеть** — основной обмен идёт с локальным демоном `127.0.0.1`. Внешние запросы: анонимная проверка обновлений на GitHub (`api.github.com`), открытый прогноз погоды и геокодинг (Open-Meteo, без ключей) и автоопределение координат по IP (`ip-api.com`) — строго анонимно, без передачи данных пользователя.
5. **Окно** не активируется и не появляется в панели задач, что снижает риск перехвата ввода.
6. **Буфер обмена** хранится только в памяти процесса (`ClipboardService`): фрагменты не пишутся на диск, не уходят в логи и не передаются по сети; выключатель `Settings.Clipboard` очищает историю.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\build.ps1
```

- Проект: `desktop/OpenIsland/OpenIsland.csproj`, имя сборки — `OpenIsland`, пространство имён — `OpenIsland`.
