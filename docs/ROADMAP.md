# Roadmap проекта OpenIsland

План развития. Отметки отражают фактическое состояние нативной WPF-версии (`desktop/OpenIsland`).

---

## 📌 Фаза 1: Фундамент и островной UI — **готово**
- [x] Высокопроизводительная нативная основа: C# WPF (.NET 8) с пружинными анимациями (Spring physics).
- [x] Нативное окно-оверлей поверх всех окон (`Topmost`, `AllowsTransparency`, `NoResize`, `WS_EX_TOOLWINDOW | NOACTIVATE`).
- [x] Корректные сквозные клики: окно-хост прозрачное, интерактивны только элементы островка.
- [x] Базовые состояния:
  - [x] **Свернутое**: капсула с часами, зарядом, индикаторами.
  - [x] **Компактно-активное**: статус агента OpenCode, медиа, таймер, запись, громкость.
  - [x] **Развернутое**: карточки меню, настроек, плеера, таймера, погоды, OpenCode и др.
  - [x] **Контекстное меню**: правый клик по островку.
- [x] Скрытие в полноэкранных приложениях, удержание поверх окон без кражи фокуса.
- [x] Настройки внешнего вида (масштаб, отступ, стекло, фон, акцент) в реестре.

## 📌 Фаза 3: Каталог ИИ-экспертов — **снято**
Первоначально планировался каталог ролей-персон (`tools/agency-agents`) с быстрыми чипами в карточке OpenCode. Перед публикацией каталог удалён как чужой артефакт, а кнопки-персоны убраны из UI: задача агенту уходит в сессию как есть, роли задаются промптом. Вместо этого реализован апдейтер через GitHub Releases.

## 📌 Фаза 4: Виджеты и системные интеграции — **готово**
- [x] Медиаплеер: интеграция с системным плеером (GSMTC), обложка, прогресс, перемотка, источник.
- [x] Плееры, которые Windows не видит (AIMP, Winamp, WACUP): резервный канал через совместимое окно `Winamp v1.x` — состояние, трек, позиция и длительность, пауза/переключение/перемотка; обложки нет (v1.2.6).
- [x] Живой спектр из реального вывода звука (WASAPI loopback).
- [x] Мини-эквалайзер, реагирующий на **любой** системный звук (капсула `View.Sound` без активного трека).
- [x] Таймер: пресеты 5/10/15/25/45 минут, точная настройка колесом от 1 до 99, пауза, кольцо прогресса, звонок отдельным пузырём.
- [x] Индикаторы громкости, заряда, наушников, сети.
- [x] Автозапуск с Windows.
- [x] **Мониторинг ПК**: карточка из меню с CPU (общая нагрузка и полоски по ядрам, до 16 — при большем числе ядра усредняются в группы), RAM, диском (активность `% Disk Time` и свободное место на системном диске), сетью (↓/↑), GPU (PDH) и температурой (WMI). Опрос идёт только пока карточка открыта (1 с под курсором, иначе 3 с), поэтому в фоне остров не нагружает систему.
- [x] Список запущенных dev-процессов и занятых локальных портов (Node, Python, Docker, Go): карточка «Процессы и порты» из меню с режимами «Dev»/«Все», портами владельца, памятью и завершением процесса в два шага (клик по строке → «Завершить»). Порты читаются через IP Helper API, опрос идёт только пока карточка открыта (v1.2.4).
- [x] Быстрые действия: **история буфера обмена** (последние 30 фрагментов, только в памяти, по клику — обратно в буфер) с переключателем в настройках.
- [x] Быстрые действия: **запуск утилит с островка** — карточка «Быстрый запуск» с 8 системными утилитами (Проводник, Терминал (Windows Terminal либо PowerShell), Калькулятор, Блокнот, Диспетчер задач, Параметры, Панель управления, Ножницы) и своими `.exe`/`.lnk`/`.bat`/`.cmd`. Список своих программ хранится в реестре (`Settings.QuickLaunch`, строки `Имя|Путь|Аргументы`), добавляется кнопкой «+ .exe» и удаляется «×»; запуск идёт через оболочку Windows, после чего остров сворачивается (v1.2.5).
- [x] **Полная кастомизация интерфейса** (v1.3.0):
  - **Архитектура тем и динамические палитры**: `ThemeService.cs`, три режима оформления (`Тёмная`, `Светлая`, `Авто` с автоматическим отслеживанием системной темы Windows `AppsUseLightTheme` через `SystemEvents.UserPreferenceChanged`).
  - **Пресеты палитр**: `Обсидиан` (классический графит), `OLED` (чистый чёрный `#000000`), `Nord` (арктический серо-синий) и `Неон / Cyberpunk` (бирюзово-пурпурные неоновые акценты).
  - **Управление видимостью виджетов в меню**: страница «Виджеты» в меню «Настройки» с отдельными переключателями для каждого виджета (OpenCode, Плеер, Буфер, Мониторинг ПК, Процессы, Быстрый запуск, Полка, Погода, Таймер) и динамически подстраивающаяся высота капсулы меню.
  - **Стили формы капсулы**: переключатель `Сквиркл` (плавное суперэллиптическое скругление Apple), `Капсула` (максимально круглые торцы), `Fluent` (современный стиль Windows 11) и `Строгая` (геометрические минималистичные скругления).
  - **Стили стекла**: тумблер стекла с выбором интенсивности `Матовое` (мягкий плотный блюр), `Тонированное` и `Кристалл` (прозрачное стекло).

> Апстрим-виджеты «Тексты песен», «Запись OBS», «Полка файлов», «Погода» и «QR-код» вырезаны из проекта. Мониторинг ПК на базе `systeminformation` был только в раннем прототипе; в нативной версии он реализован заново (`PerfService`).

## 📌 Фаза 10: Живой силуэт — живая кромка и дыхание — **отложено после прототипа**
Самый заметный приём из разбора Island: силуэт пилюли перестаёт быть статичным. Подробный дизайн и итог прототипа — `docs/ARCHITECTURE.md` §3.4.

> **Прототип (v1.2.0) не оправдал ожиданий.** Волнистая нижняя кромка по 16 полосам спектра, при обоих направлениях гребней, выглядит на компактной пилюле как «погрызенный край», а не как жидкий силуэт. Код откачен. Для фичи нужен отдельный R&D: безье-сглаживание контура, наружные всплески, возможно метаболы. Пункты ниже возвращаются в работу только после такого захода.

- [ ] `EdgeWave.cs`: нижний контур пилюли как `StreamGeometry` из 16 полос `SpectrumLevels` (один путь за кадр, без `Geometry.Combine` на каждый зуб).
- [ ] Тинт кромки обложкой/акцентом без отдельной отрисовки — за счёт существующей обводки `_edge` в `Goo.DrawBody`.
- [ ] Плавный вход/выход волны по старту и остановке звука; ревизия кромки в `Body.SetShape`, иначе не перерисуется при неподвижной геометрии.
- [ ] Дыхание в покое и «провис» без курсора: живой режим `_shapeLoop` на ~20 кадрах в секунду.

## 💡 Фаза 11 (идея, не начато): Островок как лаунчер

«Лаунчер» здесь — это сам островок, а не отдельное приложение: одна точка входа для повседневных дел, а не оболочка вокруг ИИ. ИИ — одна из функций, а не центр экрана.

- Универсальные действия без ИИ: запуск приложений из меню «Пуск», системные действия (таймер, громкость, скриншот, блокировка, сон, корзина), вычисления и конвертация (`= 12*8`, `30 usd в rub`), файлы и папки, окна/процессы/порты (закрывает пункт Фазы 4), буфер обмена. Карточка «Быстрый запуск» (Фаза 4) — готовая основа для системных действий, но без поиска и ввода.
- Строка «Спросить ИИ» — одна из возможностей, а не главный экран; действия от модели только после подтверждения, без авто-выполнения.
- Два режима ввода: обычные фразы для новичков («таймер на 10 минут», «что занимает порт 3000») и префиксы для опытных (`>`, `=`, `/`, `@`).
- Открытые вопросы: как это живёт внутри островка (отдельная карточка «Открыть» с полем ввода против расширения существующих карточек); хоткей; насколько глубоко делать поиск файлов (Windows Search vs собственный индекс).

## 📌 Фаза 12: Мультизадачный Dynamic Island и микро-индикаторы (по мотивам islandcn) — **в планах / R&D**

Анализ архитектуры веб-библиотеки `opencoredev/islandcn` (React/shadcn): покадровая калибровка пружин по эталону iOS, 4-уровневый стек состояний (Idle / Compact / Split / Expanded) и микро-индикаторы активностей.

- [ ] **Полноценный режим `Split` (двойная капсула для двух одновременных задач)**:
  - *Суть*: Если в системе активны два процесса одновременно (например: агент OpenCode думает/стримит ответ + тикает фоновый таймер; или играет музыка GSMTC + на полку файлов брошен документ), остров физически разделяется на центральную пилюлю (главный процесс) и отдельный круглый пузырёк справа (вторичный процесс).
  - *Подсказка по реализации*:
    - **Геометрия** (`MainWindow.Shape.cs`): переход от единого пути к составной геометрии (`_splitBubbleSpring` для координаты $X$ и радиуса $R$ отделившегося пузырька).
    - **Жидкий разрыв** (`Goo.cs`): органический эффект метаболов — пилюля вытягивается вправо, перемычка истончается и с мягким звуковым микро-эффектом (`SoundFx.cs`) рвётся, отпуская пузырёк на расстояние ~8–12 px с живым отскоком.
    - **Интерактивность**: клик по основной капсуле открывает карточку главной активности (OpenCode), клик по пузырьку — вторичной (таймер/плеер).
    - **Приоритеты активностей** (`ActivityPriority`): Будильник/Алерт > OpenCode выполнение > Плеер/Звук > Тикающий таймер > Загрузка файлов > Индикатор записи.

- [ ] **Кольцевой индикатор прогресса (Progress Ring в компактном островке)**:
  - *Суть*: Замена текстовых процентов (`45%`) или широких полос компактным круговым индикатором с непрерывной пружинной анимацией заполнения дуги вокруг пиктограммы.

      - Полке файлов (анимация приёма/загрузки перетаскиваемого файла).
      - Зарядке батареи (пульсирующее кольцо уровня заряда при подключении).
    - Динамический цвет дуги: адаптация под акцентный цвет темы (`ThemeService.Accent`) или цвет обложки играющего трека.

- [ ] **Индикатор активной записи и микрофона (Recording Indicator)**:
  - *Суть*: Отображение в свёрнутой пилюле мягко пульсирующей оранжево-красной точки и компактного хронометража (`00:14`), когда приложение или система захватывают микрофон либо ведут запись экрана/звука.
  - *Подсказка по реализации*:
    - **Детект микрофона в Windows 10/11**: опрос системного реестра `HKCU\Software\Microsoft\Windows\CurrentVersion\CapabilityAccessManager\ConsentStore\microphone\NonPackaged` (значение `LastUsedTimeStop == 0` сигнализирует об активном захвате) либо через WASAPI `IAudioSessionManager2`.
    - **Анимация точки**: синусоидальный пульс свечения `GlowPulse` без пересоздания WPF-кистей (анимация `Opacity` или радиуса через `ScaleTransform`).
    - **Интерактивность**: клик по индикатору показывает всплывающий тост или мини-карточку с именем процесса, использующего микрофон (Discord, OBS, браузер, Telegram).

- [ ] **Калибровка физики пружин под стандарт Apple (Response & Damping)**:
  - *Суть*: Приведение пружинных анимаций OpenIsland к покадровому эталону iOS Dynamic Island на основе замедленных съёмок Apple.
  - *Подсказка по реализации*:
    - В формулах Apple Motion физика задаётся не «жёсткостью» и «трением», а параметрами `response` (длительность полупериода колебаний в секундах, обычно 0.35–0.45s) и `dampingRatio` (0.7–0.8 — живой отскок, 1.0 — критическое затухание).
    - Формулы пересчёта для нашей структуры `Spring.cs`:
      $k = (2\pi / \text{response})^2$, $c = 4\pi \cdot \text{dampingRatio} / \text{response}$.
    - Применить калибровку для фаз:
      - `Expand`: лёгкий упреждающий овершут по ширине перед вытягиванием высоты.
      - `Collapse`: быстрый динамический подскок с мягким приземлением в пилюлю.
      - `Bounce`: упругий отклик при переключении треков или смене статусов агента.
