# Roadmap проекта OpenIsland

План развития. Отметки отражают фактическое состояние нативной WPF-версии (`desktop/OpenIsland`).

---

## 📌 Фаза 1: Фундамент и островной UI — **готово**
- [x] Высокопроизводительная нативная основа: C# WPF (.NET 8) с пружинными анимациями (Spring physics).
- [x] Нативное окно-оверлей поверх всех окон (`Topmost`, `AllowsTransparency`, `NoResize`, `WS_EX_TOOLWINDOW | NOACTIVATE`).
- [x] Корректные сквозные клики: окно-хост прозрачное, интерактивны только элементы островка.
- [x] Базовые состояния:
  - [x] **Свернутое**: капсула с часами, зарядом, индикаторами.
  - [x] **Компактно-активное**: статус агента OpenCode, медиа, таймер, запись, громкость.
  - [x] **Развернутое**: карточки меню, настроек, плеера, таймера, погоды, OpenCode и др.
  - [x] **Контекстное меню**: правый клик по островку.
- [x] Скрытие в полноэкранных приложениях, удержание поверх окон без кражи фокуса.
- [x] Настройки внешнего вида (масштаб, отступ, стекло, фон, акцент) в реестре.

---

## 📌 Фаза 2: Интеграция с OpenCode — **готово**
- [x] Автоматическое обнаружение демона OpenCode (`opencode service status`, проверка `/api/info`, повторный поиск при смене порта).
- [x] Автоматический пейринг (`opencode pair`) и получение токена без ручного ввода.
- [x] Шифрованное хранение токена через Windows DPAPI (`%LOCALAPPDATA%\OpenIsland\opencode-token.bin`), миграция старого plaintext-файла.
- [x] Нативный клиент `OpenCodeService.cs` (REST + SSE).
- [x] Список сессий и активного статуса (`/api/session`, `/api/session/active`).
- [x] Список моделей и переключение модели сессии (`/api/model`, `/api/session/{id}/model`).
- [x] Отправка промптов/задач агенту из островка (`/api/session/{id}/prompt`).
- [x] Живой стриминг ответа и статуса через SSE (`/api/event`).
- [x] Создание, переключение и удаление сессий из карточки OpenCode.
- [x] Остановка выполнения (`/api/session/{id}/interrupt`).
- [x] Диагностический прогон `--selftest` (сессии, модели, промпт, ответ).

---

## 📌 Фаза 3: Каталог ИИ-экспертов — **снято**
Первоначально планировался каталог ролей-персон (`tools/agency-agents`) с быстрыми чипами в карточке OpenCode. Перед публикацией каталог удалён как чужой артефакт, а кнопки-персоны убраны из UI: задача агенту уходит в сессию как есть, роли задаются промптом. Вместо этого реализован апдейтер через GitHub Releases.

---

## 📌 Фаза 4: Виджеты и системные интеграции — **в работе**
- [x] Медиаплеер: интеграция с системным плеером (GSMTC), обложка, прогресс, перемотка, источник.
- [ ] Плееры, которые Windows не видит (AIMP, Winamp): GSMTC о них не сообщает, остров их не показывает. Пробел подтверждён разбором Island (§7.2 в `PRODUCT.md`).
- [x] Живой спектр из реального вывода звука (WASAPI loopback).
- [x] Мини-эквалайзер, реагирующий на **любой** системный звук (капсула `View.Sound` без активного трека).
- [x] Таймер: пресеты 5/10/15/25/45 минут, точная настройка колесом от 1 до 99, пауза, кольцо прогресса, звонок отдельным пузырём.
- [x] Индикаторы громкости, заряда, наушников, сети.
- [x] Автозапуск с Windows.
- [x] **Мониторинг ПК**: карточка из меню с CPU (общая нагрузка и полоски по ядрам, до 16 — при большем числе ядра усредняются в группы), RAM, диском (активность `% Disk Time` и свободное место на системном диске), сетью (↓/↑), GPU (PDH) и температурой (WMI). Опрос идёт только пока карточка открыта (1 с под курсором, иначе 3 с), поэтому в фоне остров не нагружает систему.
- [ ] Список запущенных dev-процессов и занятых локальных портов (Node, Python, Docker, Go).
- [x] Быстрые действия: **история буфера обмена** (последние 30 фрагментов, только в памяти, по клику — обратно в буфер) с переключателем в настройках.
- [ ] Быстрые действия: запуск утилит с островка.

> Апстрим-виджеты «Тексты песен», «Запись OBS», «Полка файлов», «Погода» и «QR-код» вырезаны из проекта. Мониторинг ПК на базе `systeminformation` был только в раннем прототипе; в нативной версии он реализован заново (`PerfService`).

## 📌 Фаза 5: Расширенные возможности OpenCode — **в работе**
- [x] SSE-стриминг событий OpenCode (`/api/event`) с автопереподключением.
- [x] Одобрение и отклонение прав агента прямо с островка (`/api/session/{id}/permission/{requestID}/reply`).
- [x] Показ ошибок выполнения и повторных попыток модели (`session.status` → `retry`).
- [ ] Просмотр диффов изменений (`/api/session/{id}/diff`) с подсветкой и переходом к файлам.
- [ ] История сообщений сессии с прокруткой (сейчас показывается последний ответ).
- [x] **Быстрое переключение сессий**: панель со списком сессий (название, папка, относительное время последней активности, точка текущей/работающей сессии) вместо перелистывания «‹ 1 / 12 ›» по одной; при 8+ сессиях появляется поиск по названию и папке. Логика списка вынесена в `SessionList.cs` и покрыта тестами.
- [x] Глобальный хоткей **Ctrl+Alt+O** — открыть/свернуть карточку OpenCode из любого приложения.
- [x] Звук завершения задачи — тот же `staplebops-01`, что играет сам OpenCode (MIT).
- [x] Уведомление Windows (тост через иконку трея) при завершении длинной задачи агента (дольше 15 с), с переключателем в настройках.

## 📌 Фаза 6 (Отложено / Future): Авторизация по персональным подпискам
- [ ] Изолированный модуль `AISessionManager` (Claude Pro, ChatGPT Plus, Gemini Advanced) на основе браузерных сессий.
- [ ] Проксирование локальных инструментов в веб-сессию для агентского цикла без API-ключей.
- [ ] Альтернатива: прямое подключение API-ключей провайдеров через настройки OpenCode.

Дизайн и ограничения описаны в [`AI_SESSION_AUTH.md`](./AI_SESSION_AUTH.md). В текущей WPF-версии используется только локальный OpenCode с его собственными провайдерами.

## 📌 Фаза 7: Кастомизация и релиз — **готово**
- [x] Настройки внешнего вида: масштаб, отступ, стекло, фон, акцент, вид эквалайзера.
- [x] Автозапуск с Windows.
- [x] Скрипт сборки `scripts/build.ps1` и запуск в один клик (`Запуск_OpenIsland.bat`).
- [x] Логи с ротацией в `%LOCALAPPDATA%\OpenIsland\logs`.
- [x] Portable-сборка: self-contained single-file `OpenIsland.exe` (без установленного .NET), собирается в релизе и проверяется в CI.
- [x] Установщик **Inno Setup**: `installer/OpenIsland.iss`, per-user (`%LOCALAPPDATA%\Programs\OpenIsland`), ярлык в «Пуск», запись в «Программы и компоненты», удаление, опциональные ярлык на рабочем столе и автозапуск. Сборка — `scripts\build.ps1 -Installer`, публикуется как `OpenIslandSetup-<версия>.exe`.
- [x] Автообновление через GitHub Releases: проверка `releases/latest`, скачивание ассета `OpenIsland.exe`, сверка `sha256`-дайджеста, подмена файла и перезапуск.
- [x] Иконка в трее: двойной клик — показать остров, правый клик — «Открыть/Скрыть остров», «Настройки», «Выход».
- [ ] Подпись исполняемого файла — **не планируется** (требует платного сертификата; SmartScreen может предупредить при установке). MSIX без доверенной подписи установить нельзя.

## 📌 Фаза 8: Качество и тесты — **в работе**
- [x] Юнит-тесты (xUnit, `tests/OpenIsland.Tests`) на чистую логику: разбор ответов OpenCode (сессии, модели, активные сессии, описания моделей), версии и changelog апдейтера, `Countdown`, инварианты настроек, история буфера обмена (дедуп, лимит 30, обрезка длинных фрагментов), список сессий (порядок/поиск/имя папки/относительное время) и агрегация ядер CPU (`PerfMath`).
- [x] Прогон тестов в CI на каждый push и PR (`dotnet test -warnaserror`).
- [ ] Тесты ретраев и ошибок сети OpenCode (нужны мок-ответы HTTP).
- [x] Диагностика OpenCode: понятные статусы сбоя (`0` → «OpenCode не отвечает», `401` → «требуется авторизация», `404` → «сессия не найдена», `409` → «сессия занята») и транзиентная надпись после удаления сессии.

## 📌 Фаза 9: Пересмотр по мотивам Island — **бэклог, ничего не начато**
Разбор чужого проекта `exuupery/island` (закрытый исходник, лицензии нет — берём только идеи) — в `PRODUCT.md`, §7. Ниже — кандидаты, отсортированные по цене. Решение по каждому пункту отдельное; полка/погода/QR/тексты песен ранее были вырезаны как апстрим-наследие (§2.5 `PRODUCT.md`) и возвращаются только как собственные нативные реализации.

- [ ] Статус агента OpenCode в **свёрнутой** пилюле (работает / спрашивает / готово) из уже приходящих SSE-событий.
- [ ] Живые событийные карточки: очередь с автосворачиванием и настраиваемым временем жизни вместо одиночного тоста.
- [ ] Светлая тема островка, отдельная прозрачность свёрнутого/раскрытого, диапазон масштаба 80–200 %.
- [ ] Сквозной режим (click-through) с хоткеем и командой.
- [ ] Автоскрытие за край экрана: список процессов-исключений и режим «не прятаться на рабочем столе».
- [ ] Остров не попадает на скриншоты и в запись (`WDA_EXCLUDEFROMCAPTURE`) — переключателем, из-за конфликтов с оверлеями NVIDIA.
- [ ] Командная строка `Alt+Space`: лаунчер, калькулятор, конвертер, «таймер 10 мин», `>` cmd/PowerShell.
- [ ] Полка файлов (drag & drop на остров) — пересмотр вырезанного.
- [ ] Погода (MET Norway, без ключа) — пересмотр вырезанного; только `async` и throttle.
- [ ] Заметка и напоминания естественным языком; тексты песен в такт (LRCLIB) — пересмотр вырезанного.
- [ ] Свой выбор аудиоустройства для громкости и микрофона.
- [ ] Инструменты: скриншот с разметкой, OCR, пипетка, запись экрана — крупный блок, отдельная оценка.

> Осознанно не берём: 25 персонажей-скинов и платный гейт (наша идентичность — нативный, лёгкий, AI-first островок) и веб-UI внутрь нативного островка.

## 📌 Фаза 10: Живой силуэт — живая кромка и дыхание — **дизайн готов, код не начат**
Самый заметный приём из разбора Island: силуэт пилюли перестаёт быть статичным. Подробный дизайн — `docs/ARCHITECTURE.md` §3.4.

- [ ] `EdgeWave.cs`: нижний контур пилюли как `StreamGeometry` из 16 полос `SpectrumLevels` (один путь за кадр, без `Geometry.Combine` на каждый зуб).
- [ ] Тинт кромки обложкой/акцентом без отдельной отрисовки — за счёт существующей обводки `_edge` в `Goo.DrawBody`.
- [ ] Плавный вход/выход волны по старту и остановке звука; ревизия кромки в `Body.SetShape`, иначе не перерисуется при неподвижной геометрии.
- [ ] Дыхание в покое и «провис» без курсора: живой режим `_shapeLoop` на ~20 кадрах в секунду.
- [ ] Жёсткие выключения живого режима: окно скрыто, остров за краем, полноэкранное приложение, морфинг и drag (правило §4.2).
- [ ] Настройки `EdgeWave`, `EdgeWaveAmplitude` (0–20 px), `Lively` + пункты на странице оформления.
- [ ] Юнит-тесты `EdgeWave` (число сегментов, ровный низ при нулевой амплитуде, точки в границах пилюли) и замер фонового CPU до/после.
- [ ] Решить открытые вопросы: шипы наружу (опция B, требует расширения `_clipRect`, `Shadow.Clip` и `Glass.Cut`) и поведение кромки в капсуле `View.Sound` без трека.
